## 2. Что перенести в новую папку

### Обязательно — весь проект целиком

**37 файлов, около 1,4 МБ.** Копировать папку `Chat_88` **вместе с `.git`** —
история коммитов и есть страховка.

| Что | Зачем именно это |
|---|---|
| `collect.py`, `check_jobs.py`, `watchdog.py`, `snapshot.py` | точки входа: сборка, перепроверка вакансий, сторож, снимки |
| `news/` (9 модулей) | вся логика: config, util, sources, fetch, filters, dedup, store, monitor, render |
| `tests/` (5 файлов) | 88 тестов на `unittest` |
| `data/` — 8 рубрик + `sources.json` | **единственная копия архива вне GitHub**, терять нельзя |
| `about/index.html`, `_category_template.html` | правятся руками, из кода не восстанавливаются |
| `.github/workflows/deploy.yml`, `watchdog.yml` | расписание сборки и сторож |
| `.gitignore`, `.gitattributes` | `data/` не игнорируется, `docs/` игнорируется, переводы строк в LF |
| `AGENTS.md` (42 КБ) | **всё устройство проекта и все грабли** — главный файл для нового чата |
| `README.md` | краткое описание для людей |
| `_snapshots/` | два снимка архива — вторая страховка |

### Не переносить

- `docs/` — пересобирается из `data/` за один запуск, это 2 МБ производного мусора.
- `_backup/` — рабочие копии правок, нужны только при разборе конкретного случая.
- `__pycache__/` — байткод.

### Что не поедет вместе с папкой

**Токен GitHub.** Лежит в `Chat_88\.git\config`, внутри адреса удалённого
репозитория. При копировании папки целиком он уедет вместе с `.git` и всё
продолжит работать. Если переносить только файлы — токен не переедет,
и `git push` перестанет работать, пока его не пропишут заново.

**В самом репозитории секретов нет** — workflows обходятся встроенным
`GITHUB_TOKEN`.

## 3. Что нужно забрать из этого диалога

Это то, чего нет в файлах проекта: договорённости, решения и найденные грабли.

### Правила работы

1. **Проект наш, не «его».** Пользователь поправил за дистанцию: «это не только
   мой проект, но по сути твой. моя только придумка, а без тебя я бы этого
   не сделал». Говорить «наш».
2. **Отвечать по-русски.** Всегда.
3. **Схема работы:** задача → короткий план → явное «ок» → выполнение.
   Исключение — тривиальные задачи в одно действие.
4. **Многошаговые задачи:** сначала полный список шагов, потом строго по одному.
   Если от пользователя нужно только «ок», а дальше работа моя — не дробить.
5. **Бэкапы** ручных файлов в `_backup/` перед правкой.
6. **Пользователь смотрит только живой сайт** → работа считается сделанной
   после commit + push, а не после «файлы поправлены».
7. **Ничего не теряется безвозвратно.** Сомнительное уезжает в Солянку,
   в подрубрику «Не фильтрованное» 🍺, а не в корзину.
8. **Факты, а не теории.** Сначала лог и данные, потом выводы.

### Решения по содержанию сайта

- **Строго про ИИ**, плюс технологии, если они связаны с ИИ.
- **Вакансии:** только онлайн/удалённые; всё на английском — отбрасывать;
  работа в офисе у работодателя не нужна; вакансия обязана быть про ИИ/ML.
- **`vc.ru` не удалять** — пользователь этот источник ценит, материалы про ИИ
  там бывают. Один раз я ошибочно записал его в мёртвые — пользователь поправил.
- **`ComNews` не подключать никогда.**
- **Название сайта — «Нейрорадар»**, выбрано из четырёх предложенных
  (Нейролента, Нейрорадар, Нейросито, Сводка по ИИ). Подзаголовок «Что нового
  в ИИ — шесть раз в день», значок 📡. Вопрос закрыт.
- **Имя репозитория** пользователю безразлично.
- **Кандидаты в источники** (Neuro-Radio 96% прохождения, Илья Егоров 72%,
  Daily Prompts 64%) и список отклонённых сайтов лежат в `AGENTS.md` —
  подключать только с явного согласия пользователя.

### Грабли, на которые уже наступали

Всё это записано в `AGENTS.md`, но стоит держать в голове:

- **«Вакансия закрыта» есть на каждой странице hh.ru** — это словарь интерфейса,
  а не признак закрытия. Я на этом ошибся и объявил закрытыми 212 вакансий
  из 217. Спасли контрольная группа открытых вакансий и проверка гипотезы.
- **Слово «офис» нельзя запрещать.** Описания hh.ru содержат «Регион: Москва»
  и «Альфа-Банк. Центральный офис» — такой запрет выкосил бы все вакансии hh.ru.
- **Поля API «Работы России»** — `job-name` и `creation-date`, а не `title`
  и `creation_date`. Из-за этого источник месяцами молчал, и ошибки не было.
- **Коммит, трогающий только `data/`, сборку не запускает** — в `deploy.yml`
  стоит `paths-ignore: ['data/**']` (защита от цикла коммитов).
- **`api.hh.ru` отдаёт 403** без токена приложения — живём на RSS.
- **Кириллица в URL** ломает `urlopen` без `quote()`.
- **Массовые миграции накопителей — только двухфазно** (сначала собрать все
  изменения, потом писать). Однажды так потеряли 701 запись.
- **Перед пушем:** `git fetch origin -q && git reset --soft FETCH_HEAD`, иначе
  push отвергается — CI сам коммитит `data/` после каждой сборки.

### Незакрытое

- `watchdog.py` ни разу не наблюдался срабатывающим по своему расписанию —
  проверялись только ручные запуски.
- 10 вакансий в накопителе перепроверить не удалось, оставлены как есть.
- `check_jobs.py --apply` пишет список из ранее прочитанного файла, поэтому
  после `collect.py` его надо запускать заново, иначе свежие вакансии затрутся.
  Правильный порядок: `check_jobs.py --apply` → `collect.py` → коммит.

## 4. Что делать в новой папке

1. Скопировать `Chat_88` целиком, вместе с `.git`, в новую папку.
2. Проверить, что код жив:
   `python -m unittest discover -s tests -t .` — ожидаем 88 тестов, OK.
3. Проверить, что сборка проходит: `python collect.py` — в конце печатается
   отчёт по источникам, в архиве около 1460 записей.
4. Если репозиторий остаётся тем же — настраивать ничего не нужно, коммиты
   и сборка продолжат работать как есть.
5. Если заводится новый репозиторий — поменять адрес в `.git/config`
   и включить Pages: `Settings → Pages → Source: GitHub Actions`.
6. В новом чате первым делом попросить: **«прочитай AGENTS.md в папке проекта»** —
   там всё устройство, порядок работы и все грабли.
