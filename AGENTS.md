### Архив и снимки

`data/*.json` — **отслеживается git**, это основной архив. Раньше накопители
жили в кэше GitHub Actions, который удаляется после 7 дней простоя, и при долгой
паузе 90 дней истории обнулялись бы до последних 20–50 записей из лент.

Вторая страховка — `_snapshots/`. Один файл `.json.gz` фиксирует всё состояние
на момент времени:

```bash
python snapshot.py save --note "повод"                 # снять снимок
python snapshot.py list                                # что есть
python snapshot.py restore _snapshots/<файл>.json.gz   # восстановить
```

1400 записей занимают ~166 КБ. Восстановление **двухфазное**: сначала проверка
снимка целиком, только потом запись. Однократно потеряли 701 запись, записав
файл раньше времени — больше так не делаем.

**Снимать снимок:** перед крупной правкой фильтров, перед массовой чисткой архива,
перед экспериментами на тех же данных, и просто раз в неделю.

## Как проходит сборка

`collect.py` вызывает шаги по порядку:

1. **Читаем ленты** (`collect_feeds`) — все 36 адресов из `news/sources.py`.
2. **Вакансии и заказы** (`collect_extra`) — hh.ru, Работа России, FL.ru.
   Они приходят не из RSS, поэтому собираются отдельно.
3. **Поднимаем архив** (`load_store`) — читаем `data/*.json`. Здесь же
   перепроверяются старые записи: если материал перестал проходить фильтр,
   он не удаляется, а переводится в «Не фильтрованное».
4. **Фильтр по дате** — старше 90 дней отсекается.
5. **Сортировка** — свежее выше.
6. **Раскладка по рубрикам** — `data/<рубрика>.json`, `docs/<рубрика>/data.js`,
   `docs/<рубрика>/index.html`.
7. **Главная** и копирование ручных страниц.

Порядок шагов важен: шаг 3 специально идёт после сбора, иначе старые записи
перезапишут свежие.

## Автообновление и сторож

Расписание GitHub Actions **ненадёжно**: cron ставит запуски в очередь, может
задержать на 30–60 минут или вообще пропустить при нагрузке. На практике запуск
в 22:00 МСК не состоялся вовсе.

Поэтому расписание продублировано сторожем:

1. `deploy.yml` — сборка по слотам каждые 4 часа (МСК 02, 06, 10, 14, 18, 22),
   плюс на push и вручную. После сборки коммитит обновлённый `data/` обратно
   в репозиторий.
2. `watchdog.yml` — каждый час в `:45`. Смотрит время последней сборки
   **на живом сайте** и сравнивает с началом текущего слота:
   - данные свежие → ничего не делает;
   - данные устарели → дёргает `workflow_dispatch` и перезапускает сборку;
   - **время прочитать не удалось → тоже перезапускает.** Раньше сторож в этом
     случае молча выходил, и «не смог прочитать» выглядело как «всё хорошо».

Слоты и допуск задаются в `watchdog.py`: `SLOT_HOURS` и `GRACE_MINUTES`.
Сторожу нужны права `actions: write` — они указаны в `watchdog.yml`.

### Ловушки, на которые уже наступили

1. **Не читать локальный `docs/ai/data.js`.** Он остаётся от прошлого запуска
   и бывает на много часов старше опубликованного. Сторож однажды увидел
   локальные `18:38` вместо онлайн `00:48` и зря дёрнул сборку.
   Единственный источник — живой сайт.
2. **Обходить кэш GitHub Pages.** Ответы отдаются с `Cache-Control: max-age=600`,
   поэтому запрос идёт с `?nocache=<время>`. Иначе можно 10 минут видеть старый
   ответ и опять дёрнуть сборку.
3. **Права токена.** Без `permissions: actions: write` `workflow_dispatch`
   возвращает 401/403 и перезапуск молча не происходит.
4. **Цикл коммитов.** Сборка коммитит `data/` в `main`. В `deploy.yml` стоит
   `paths-ignore: ['data/**']` и `[skip ci]` в сообщении — иначе каждый коммит
   запускал бы новую сборку, и это никогда бы не остановилось.

## Фильтрация: только про ИИ

Сайт — агрегатор **исключительно про ИИ**. Всё остальное отбрасывается.
При этом технологии и наука тоже допустимы — если они связаны с ИИ.

- `has_ai_signal(text)` — ищет сильные маркеры (`AI_STRONG` + `AI_NAMES` +
  отдельное слово «AI»).
- `is_ai_relevant(text, cat)` — пропускает материал, только если сигнал есть.
  Дополнительно отсекает бытовые ложные срабатывания (`FALSE_POSITIVES`:
  стиральные машины, дизайн интерьера и прочее, где «ИИ» — маркетинговая приписка).
- `classify()` возвращает `None`, если материал вообще не про ИИ.
- Рубрики `jobs` и `orders` эту проверку не проходят — у них свои фильтры.
- **Вакансии из RSS не берутся вообще.** `_build_item()` перенаправляет
  `cat == "jobs"` в `misc`: настоящие вакансии приходят только с hh.ru.
- Короткие ИИ-названия (`AI_NAMES_WORD`: `llama`, `sora`, `grok`, `qwen`, `xai`,
  `mistral`) ищутся **отдельным словом**. Иначе `llama` ловится в домене
  `wisellama.rocks` из ссылок Hacker News.
- «AI» ищется отдельным словом, но с исключением для перечисления графических
  форматов: `svg, ai, pdf` — это Adobe Illustrator, а не искусственный интеллект.

### Ловушки ключевых слов (уже наступали)

1. **Не добавлять в `CAT_KEYWORDS["jobs"]` словоформы `работа` / `подработка`.**
   Они ловятся внутри «работать», и в рубрику «Вакансии» уехало 33 статьи:
   «Россиянам придётся работать до 4 месяцев ради iPhone». Только точные формы:
   `работа вахтой`, `работа удалённо`.
2. **Не подключать источники без темы ИИ.** ТАСС Наука давала научпоп
   (рачки, ITER, чёрные дыры) — он не проходил фильтр и оседал мусором
   даже в вакансиях.
3. **Архив не чистится сам.** Фильтр проверяет только новые поступления,
   поэтому старый мусор возвращался в каждую сборку (однажды накопилось 47% набора).
   Шаг 3 в `collect.py` при каждой сборке переводит такое в «Не фильтрованное».

## Мёртвые источники (`DEAD_SOURCES`)

Убранный из `FEEDS` источник **не исчезает с сайта**: его материалы уже лежат
в архиве и продолжают публиковаться. Именно так ТАСС Наука «висел на главной»
уже после удаления из списка лент.

Поэтому в `news/config.py` есть набор `DEAD_SOURCES` — записи этих источников
отбрасываются в **двух местах**:
- `parse_rss()` — на входе (если лента случайно вернётся в `FEEDS`);
- шаг 3 в `collect.py` — при загрузке архива, счётчик печатается как `[чистка]`.

Текущий список: `ТАСС Наука` (научпоп не про ИИ), `NYT Tech` (404),
`Cossa` (закрылась), `AWS` (лента не отдаётся), `ComNews` (по 1 записи, и та не про ИИ).

**`ComNews` не подключать НИКОГДА** — по прямому указанию пользователя.

**`vc.ru` в этом списке был ошибочно.** Лента живая, материалы про ИИ бывают —
источник снова в `FEEDS`, но берём **только теги** `/rss/tag/ai` и
`/rss/tag/нейросети`: общая лента тащит бизнес, маркетинг и личные истории.
Не удалять vc.ru из `FEEDS` без проверки — пользователь ценит этот источник.

**Порядок удаления источника:** убрать из `FEEDS` → добавить в `DEAD_SOURCES` →
пересобрать (шаг 3 сам вычистит архив).

## SEO-мусор в тегах (`is_seo_spam`)

ИИ-теги vc.ru забиты рекламными заголовками вида «нейросеть для X бесплатно:
промпт и сервисы» — один автор залил 14 почти одинаковых за ночь. Плюс пустышки
вроде «Запись в сообществе AI».

Для них есть `SEO_SPAM` + `is_seo_spam()`, применяется **только** к источникам
из `SPAM_FILTER_SOURCES` (`{"vc.ru"}`), чтобы не задеть обычные ленты.
Главный маркер — слово `бесплатно` в заголовке: реальные статьи так не называют.
Из 34 записей vc.ru фильтр отсеивает 16, оставляя 18 нормальных.

Фильтр работает **на входе**, поэтому записи, успевшие попасть в архив до его
введения, надо вычищать отдельным проходом.

## Кириллица в URL лент

`urlopen` не умеет кодировать не-ASCII в адресе и падает с
`'ascii' codec can't encode`. Лента `vc.ru/rss/tag/нейросети` из-за этого
не читалась. В `fetch_url()` добавлен `quote(url, safe=":/?#[]@!$&'()*+,;=%~")` —
кодирует только не-ASCII, обычные адреса не трогает.

## Дедупликация

Одну и ту же новость легко получить дважды, поэтому проверок две:

1. **Ссылка** — точное совпадение.
2. **Ключ `источник + заголовок + дата`** (`dedup_key` в `news/dedup.py`).

Первого мало: реальный случай — vc.ru отдал статью `3139979` в тегах `#ai` и
`#нейросети` с разными слагами, и она висела на сайте двумя карточками.
Второго тоже мало: две разные новости могут совпасть по ссылке после редиректа.

Дата в ключе защищает еженедельные дайджесты с одинаковым названием, источник —
разные издания об одном событии. Заголовок сравнивается через `norm_title()`:
без регистра, пунктуации и лишних пробелов.

Проверка идёт и для свежих записей, и для архива — поэтому старый дубль
чинится сам при следующей сборке.

**Не пугаться больших чисел в счётчике `[дедуп]`.** 400–500 повторов за сборку —
это норма: пересечение архива и свежих лент. Однажды я принял это за ложные
склейки и зря паниковал. Сначала измерь, из чего складывается число.

## Солянка (`misc`)

Всё про ИИ, что не влезло в другие рубрики. Внутри три подрубрики
(`MISC_TYPES` в `news/config.py`):

| Ключ | Название | Что попадает |
|---|---|---|
| `raznoe` | 📰 Разное | обычные материалы |
| `curio` | 🤪 Курьёзы | шутки, мемы, нелепые истории, скандалы, фейлы |
| `unfiltered` | 🍺 Не фильтрованное | карантин: записи, которые перестали проходить фильтр |

**«Не фильтрованное» — карантин вместо удаления.** Если старая запись больше
не проходит правила, она не выбрасывается, а переезжает сюда. Принцип проекта:
ничего не теряется безвозвратно. Название придумал пользователь — «как пиво».

Маркеры курьёзов (`CURIO_MARKERS`) описывают только то, что мы **оповещаем**:
шутки, мемы, нелепости, скандалы. Никаких «советов» и «лайфхаков» — мы не советуем,
мы оповещаем.

## Вакансии (`jobs`) и заказы (`orders`)

**Вакансии** приходят только с hh.ru и Работы России — из RSS они не берутся.
Подкатегории задаёт `classify_job()`: AI-разработка, Разработка, Дизайн,
Тестирование. `is_real_ai_job()` отсекает продажи, HR, маркетинг, курсы
и офисную работу без удалёнки.

**Заказы** приходят только с FL.ru (`fetch_fl_orders`). Отдельная особенность:
заказ на **сайт** проходит даже без упоминания ИИ — веб-разработка это
самостоятельное направление рубрики (`SITE_MARKERS`). Подкатегории задаёт
`classify_order()`: Сайты, Промты, AI-разработка, Изображения, Видео и аудио,
Автоматизация.

   `application/rss` и `href="...rss..."` в HTML главной.
2. Посчитать `<item>` / `<entry>` в ответе — если ноль, лента не работает.
3. Посмотреть `pubDate` **последней** записи: если свежести нет неделями — сайт мёртв.

## Тесты

`tests/` на стандартном `unittest`, без внешних зависимостей. Каждый случай —
реальная ситуация, которая уже случалась в проекте, чтобы она не вернулась.

```bash
python -m unittest discover -s tests -t .
```

| Файл | Что проверяет |

### Чего сознательно НЕ делаем

- **Не переписываем чужие статьи.** Мы агрегатор, а не редакция. Переписать
  чужой текст и выдать за свой — это и авторское право, и обман читателя.
- **Никаких внешних зависимостей** (`feedparser`, `requests`) — стандартная
  библиотека делает то же самое.
- **Никакого VPS** — GitHub Actions справляется на бесплатном тарифе.
- **Никакой монетизации.**
- **Никакого Telegram-бота** — нужен сервер, токен и номер телефона.
