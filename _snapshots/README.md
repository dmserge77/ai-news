# _snapshots — снимки архива новостей

## Зачем это здесь

Архив лежит в `data/*.json` и **хранится в git** — это основной источник.
Снимок нужен как вторая страховка: он одним файлом фиксирует всё состояние
на момент времени, независимо от истории коммитов.

Если правка фильтров, массовая чистка или неудачная сборка что-то испортят,
из снимка можно поднять архив обратно, не разбираясь с `git log`.

Папка **отслеживается git** — в отличие от `_backup/`, которая в `.gitignore`.
Смысл именно в этом: снимок должен пережить и потерю машины, и сбой в репозитории.

## Как снять снимок

```bash
python snapshot.py save --note "причина или повод"
```

Появится `_snapshots/news-ГГГГ-ММ-ДД_ЧЧММ.json.gz` — один сжатый файл со всеми
8 рубриками. 1400 записей занимают ~166 КБ.

## Как восстановить

```bash
python snapshot.py list                                # посмотреть, что есть
python snapshot.py restore _snapshots/<файл>.json.gz   # разложить обратно
```

Скрипт работает в два этапа: сначала читает и проверяет снимок целиком, только
потом пишет файлы. Это защита от повторения истории, когда массовая миграция
потеряла 701 запись, записав файл раньше времени.

Проверено 15.09.2026: намеренно испорченные `agent` и `platform` восстановились
побайтово точно — все 8 рубрик совпали с резервной копией.

## Когда снимать

- перед крупной правкой фильтров или `collect.py`;
- перед массовой чисткой архива;
- перед экспериментами на тех же данных;
- просто раз в неделю, для спокойствия.

Снимки — обычные файлы, старые можно удалять: `git rm _snapshots/<старый>.json.gz`.
